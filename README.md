# Jagged clinical AI profiles

John Britton’s May 2026 scoping review compiled published AI benchmark results across psychology and adjacent tasks. The analysis asks how much a model’s performance varies between areas such as knowledge recall, differential diagnosis, crisis judgment and multi-turn support. [Read the Substack article](https://localscribe.substack.com/p/what-psychology-benchmarks-show-about).

**Start with the master CSV for the full review and the audit notes for interpretation.** The public package preserves the historical values used for the analysis. Every row has an audit disposition. The report explains discrepancies, invalid scores, qualified values, and the nine CounselingBench records whose exact source could not be established. [Download the master observations](data/master_observations.csv) · [Read the audit](review/AUDIT.md)

| File in data/ | What one row represents |
| --- | --- |
| master_observations.csv | One compiled observation. The record_type column splits 1,320 benchmark records from 150 supplemental findings. |
| benchmark_results_long.csv | A benchmark, evaluated entity, dimension and source. Raw model names, reported score text, numeric scores and provenance are retained. |
| supplemental_findings.csv | A contextual result with source and original verification status. Includes the SIRI-2 appendix records used by the analysis. |
| model_metadata.csv | One normalized entity label. The 192 entries include human baselines, datasets and frameworks. |
| benchmark_map.csv | One benchmark variant, its scoring direction, task grouping and intended analysis role. |
| blog_benchmark_rows_for_visuals.csv | One retained headline row with the raw value, score transformation and article family. |
| blog_jagged_profile_moral_combined.csv | One entity and capability family, averaged across available headline rows. |
| blog_score_review_moral_combined_4plus.csv | One entity with at least four benchmark variants. The family_count field supplies the stricter figure filter. |
| frontier_healthbench_comparison.csv | Historical external comparison metadata used by the table builder. |
| inconsistencies.csv / needs_papers.csv | Source-project cautions and unresolved requests for primary evidence. |

A missing score or capability family denotes missing evidence. The tables contain aggregate results reported under different prompts, rubrics and evaluation designs. They support descriptive comparisons. They provide no estimate of a model's performance with patients.

The source-audit rerun put GPT-4o’s overall score at **74.5 across 10 benchmark variants and seven capability families**. The article’s original estimate was 74.1. Both headline correlations still round to their published values. [See what changed in the rerun](review/AUDIT.md#impact-on-the-published-results).

## Reproduction

Run `python verify.py` with Python 3.10 or later to check the release and recompute both correlations from the observed scores. The verifier uses the Python standard library.

To rebuild the analysis from the original compiled benchmark and supplemental tables, run the following commands from a fresh copy of the repository. The builders write derived files into data/ and outputs/visuals/. The intermediate CSVs and JSON copies generated by the rebuild are ignored by Git. The tested environment used Python 3.14.

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python build_psych_analysis_tables.py
python generate_observed_figures.py
python verify.py
```

The first script implements the original review’s broader analysis. The second applies the article-specific aggregation and recreates the two observed figures. For the article, use the three CSVs beginning with blog_. Other composite tables produced by the first script use different scoring conventions. The inputs are frozen historical exports, including the Artificial Analysis index values matched at the time.

For attribution, cite John Britton’s article and the primary studies behind any scores you reuse. Source labels and provenance are carried forward from the compilation. The audit ledgers record the paper and table for each checked value.
